=== richTextSection
heading: A migration plan built around search

Moving away from WordPress is more than copying posts into a new database. Your search visibility depends on URLs, internal links, metadata, rendered content and the way search engines can crawl your site. A headless architecture changes how content reaches the browser, so those details need a place in the migration plan.

{{brand}} starts by documenting the current site and identifying the pages that matter to your business. We map existing URLs to their destinations, carry over relevant content and metadata, and design content models that editors can use without rebuilding every page by hand.

Before launch, we check the new site against the old one and test how search engines can access its pages. The work includes:

- Mapping existing URLs and testing permanent redirects where paths change
- Preserving page titles, descriptions, canonical tags and structured data where applicable
- Checking rendered content, internal links, XML sitemaps and indexability
- Keeping staging pages out of search results and monitoring the live site after launch

No migration can guarantee unchanged rankings or traffic. Search results also move for reasons outside a website release. A baseline and a launch checklist make it easier to spot migration-related issues and act on them quickly.

Start with a [CMS and performance audit]({{site}}/cms-audit/) to understand the technical and editorial work before choosing a migration route.

=== faqList
heading: WordPress to headless migration FAQs
- Will a migration preserve all our search traffic? | No agency can guarantee unchanged rankings or traffic. A thorough URL map, content checks and post-launch monitoring reduce migration risks and help identify problems.
- Can we keep our existing URLs? | Often, yes, if the new front end is configured to use the same paths. Where a path must change, use a permanent redirect to the closest relevant page.
- How long does migration take? | The plan above illustrates a six-week migration. The actual schedule depends on content volume, integrations, page complexity and the state of the existing site.
- What happens to our WordPress content? | Content is mapped from WordPress fields into the new CMS model and imported. The migrated pages should then be checked for missing text, media, links and metadata.
- Will editors still be able to publish pages? | Yes, editors publish through the chosen headless CMS rather than the WordPress interface. The content model and workflow should be designed around the team's needs.
- Does headless automatically improve SEO? | No. Search performance depends on implementation, including accessible rendered content, metadata, routing and site performance.
